Mote architecture research

Making dictation insertion dependable across macOS

A source-backed, adversarial review of Accessibility, synthetic input, clipboard paste, InputMethodKit, and the limits behind the phrase “works in any app.”

Executive decision

Keep the foundation. Replace the single-path strategy.

Mote should use a capability-driven, verified hybrid. Accessibility and Unicode events remain valuable privacy-forward layers. Clipboard paste becomes a protected compatibility fallback. InputMethodKit gets a time-boxed prototype—not a rewrite. The system must protect focus, reject dangerous destinations, verify what it can, and never lose the transcript.

The standard is dependable delivery—not one API

A successful demo in one editor is not a product guarantee. Mote needs a measurable contract that treats wrong-target insertion as worse than a safe refusal.

≥99% First-attempt, verified insertion across the published matrix of supported editable controls.
0 Wrong-target insertions across randomized focus, window, tab, and modal transitions.
100% Transcript recovery after blocked, cancelled, unobservable, or failed delivery.
Recommended product language

“Dictate into virtually any standard editable text field on your Mac.” If “any app” appears in short marketing copy, nearby support material should explicitly name secure fields, protected surfaces, remote desktops, custom canvases, and app-controlled paste restrictions.

What Mote does today

The recent Electron and Chromium fixes are not random app patches. They are documented framework capability switches. The brittleness comes from what Mote assumes after discovering the target.

Hot-key down Capture the frontmost process and focused Accessibility element before asynchronous transcription.
Target probe System-wide focus → application focus → AXManualAccessibility → AXEnhancedUserInterface.
Transcription Speech is processed locally while the original destination is retained.
Revalidation Require the original element, or currently allow a replacement target when the same app remains frontmost.
Global adapter Either Unicode CGEvents or clipboard replacement plus synthetic Command-V, based on a user-wide setting.

Capturing the destination at key-down is a sound design. The pasteboard ownership guard is also good: Mote restores the previous clipboard only if its change count still proves ownership. Carbon hot-key registration avoids global keylogging and therefore avoids an unnecessary Input Monitoring permission.

The weak points are downstream: four role names define “editable,” a disappearance of the Accessibility element can be accepted as long as the same app remains frontmost, Core Graphics accepting an event is treated as the editor accepting text, and the user must choose one delivery mechanism globally.

The hard platform truth

macOS exposes multiple text-input paths because applications do not share one universal insertion contract.

Secure and protected fields

NSSecureTextField exists specifically for secret entry and macOS exposes a secure Accessibility subrole.2, 6 Terminal’s Secure Keyboard Entry can intentionally break applications that require access to keystrokes.9

Custom rendering

Standard controls inherit accessibility behavior; custom controls only expose useful semantics when their developers implement it.4 Games, canvases, and proprietary editors can have a visible caret without an editable AX node.

Terminals and policy

macOS can warn about or block suspicious terminal pastes.10 Remote sessions, virtual machines, and enterprise products may block clipboard transfer entirely, a limitation also documented by Wispr.21, 22

Distribution constraints

Mac App Store distribution requires App Sandbox, which restricts broad control of other apps. Developer ID distribution allows Mote’s assistive design, but it does not grant a universal text API.7, 8

No public macOS API can guarantee insertion into every visible caret. The honest engineering target is broad coverage, provable safety, and deterministic recovery.

Why direct CGEvent typing is not universal

Apple says an application framework may ignore the Unicode string attached to a synthetic keyboard event and instead translate the virtual key and keyboard state itself.5 Event posting therefore proves transport to the event system—not insertion into the editor. Tools such as Espanso expose injection delays and automatically change backends for longer strings because real applications can drop or mishandle event streams.23

Mote’s fixed 16-unit UTF-16 slicing is another correctness risk. Supplementary Unicode characters use surrogate pairs, while user-perceived characters can comprise multiple scalars, such as combining accents and family emoji.15, 16 Chunks must end at extended-grapheme boundaries and be paced adaptively.

Why clipboard paste is broad—but not neutral

Paste lets the target perform its own native insertion and efficiently handles long, multiline text. Wispr’s support documentation confirms that Flow temporarily replaces and restores the clipboard; TypeWhisper and Dictum use comparable fallbacks.21, 24, 25

But the general pasteboard is shared and participates in Universal Clipboard by default.17 The change count can protect a later user clipboard change, but it cannot prove that the target consumed the paste.18 macOS 26 Clipboard History may retain copied material after Mote restores the front item, so restoration does not mean erasure.19 New pasteboard-access policy can also make programmatic reads user-visible.20

Why direct Accessibility writes deserve a place

Editable Accessibility objects may expose a settable selected-text attribute.1, 3 Mote can snapshot the selection, set the replacement, and read back the expected delta. TypeWhisper demonstrates this verified-first pattern before falling back to paste.24 The limitation is coverage: many rich, web, and custom editors do not expose a reliable setter.

Why InputMethodKit should remain an experiment

InputMethodKit is Apple’s semantic architecture for input sources. An IMKServer manages client connections, an IMKInputController exists per input session, and the client conforms to IMKTextInput.26–28 It is conceptually cleaner than paste or raw events.

It is not an invisible insertion endpoint. Users must install, enable, and select an input source. Apple’s installation guidance points to the Input Sources pane, and mature open-source IME Squirrel warns that first installation can require logout/login.13, 14 It can disrupt users with multiple keyboard layouts or language IMEs and still cannot control secure, custom, or remote surfaces.

The internal argument

Three plausible “simple” answers were argued to their strongest form. Each contains one essential truth—and one fatal blind spot.

Privacy advocate

Keep direct typing as default

Dictation can contain customer data, health information, credentials, or unreleased work. Avoiding the general pasteboard is a real privacy benefit, and direct events preserve a one-install experience.

Blind spot

Apple does not guarantee the Unicode payload is honored. A private path that silently loses text is not dependable.

Compatibility advocate

Make clipboard paste the default

Editors already know how to paste. It handles long text efficiently, and established dictation and expansion tools use it in production.

Blind spot

The pasteboard is a system trust boundary: history, syncing, DLP, clipboard managers, remote sessions, and consumption races all matter.

Platform purist

Rewrite around InputMethodKit

A real input method speaks the semantic text protocol and avoids both clipboard exposure and low-level event translation.

Blind spot

Installation, activation, keyboard-layout coexistence, and session semantics directly conflict with Mote’s frictionless product goal.

Adjudication

Universal injection is the wrong abstraction

Mote is a reliable transcript-delivery system operating across surfaces with different capabilities. Its contract should be: deliver privately and automatically when success can be established; otherwise stop safely, preserve the transcript, explain the reason in one sentence, and offer one-action recovery.

Recommended target architecture

The moat is a generic delivery engine that knows what it can prove—not a growing list of bundle-ID exceptions.

AutomaticRecommended
Select the least invasive method with demonstrated reliability for this surface and content. Prefer verified paths.
Privacy-first
Never put a transcript on the general pasteboard. Retain it when AX or direct events cannot safely deliver.
Compatibility
Use protected clipboard paste earlier, with explicit disclosure of Clipboard History and system visibility.

1. Destination guardian

At hot-key down, capture PID, bundle and app versions, window identity, the focused Accessibility element and role/subrole, readable selection state, and a monotonic focus-generation value. Use AXObserver focus/window events plus workspace activation notifications through capture and transcription.

If the app, window, or focus generation changes, cancel automatic insertion and preserve the transcript. A dynamic editor may rebind once only inside the same process and window, to a compatible focused descendant, when no focus-change event occurred. This replaces today’s unsafe “same app is still frontmost” escape hatch.

2. Capability probe

Probe system-wide focus, application focus, then the framework accessibility switches. Electron documents AXManualAccessibility; Chromium observes AXEnhancedUserInterface before constructing its full accessibility tree.11, 12 Warm this tree at app activation or dictation start, not only after a release-time failure, and measure the performance cost.

Replace the four-role allowlist with a capability record: secure subrole, selected text readable/settable, value readable/settable, selection range availability, and observed adapter reliability. A role is evidence, not authority.

3. Policy engine

1

Refuse. Stop at secure fields, protected surfaces, read-only controls, or ambiguous destinations. Keep the transcript.

2

Write semantically. If AX selected text is settable and observable, replace it and verify the expected delta.

3

Type privately. Use grapheme-safe, paced CGEvents when this surface/content profile has demonstrated reliability.

4

Paste compatibly. Use a host-only, ownership-guarded clipboard transaction when it is the safer compatibility choice.

5

Recover. If delivery is blocked or unobservable, do not blindly retry and risk duplication. Offer Paste last transcript, Copy, and Try again here.

4. Verified adapters

Accessibility adapter

Require a nonsecure settable selection, snapshot observable state, write selected text, and poll briefly for the expected change. An AX success code alone is not success.

Direct-event adapter

Chunk at grapheme boundaries, pace adaptively, separate short and long text policy, manage modifiers, and label unobservable delivery honestly.

Clipboard adapter

Snapshot every item/type; use .currentHostOnly; verify when possible; restore only while Mote owns the pasteboard; disclose Clipboard History.

Recovery adapter

Retain the last transcript and give specific failure reasons. Never automatically send a second copy after an unverified attempt.

5. Local compatibility memory

After verified attempts, record only coarse capabilities keyed by bundle ID, app version, OS version, and surface class—never transcript or field content. Expire records after app or OS updates and expose a reset. This avoids repeating known-bad paths without turning the code into a bundle-ID switchboard.

Terminal policy needs special care.

Preserve literal text, disable smart formatting, never synthesize Return, and do not turn a paste warning into command execution. Codex CLI and Claude Code must be tested both locally and through SSH/tmux.

InputMethodKit: a spike with kill criteria

Build a signed minimal input-source helper to answer the unknowns. It should not block v1.

  • Install, enable, select, upgrade, disable, and uninstall cleanly.
  • Measure whether logout/login is required on every supported macOS release.
  • Commit asynchronous transcription to the original client session.
  • Return to the user’s normal input source without disruption.
  • Coexist with CJK/RTL IMEs and multiple keyboard layouts.
  • Refuse secure fields and cancel on focus changes.
  • Test AppKit, SwiftUI, browsers, Electron, Office, and terminals.
  • Compare measured private coverage with the hybrid engine.
Kill it

if normal installation requires logout/login, Mote must remain the active keyboard source, switching is visible or disruptive, or the verified coverage gain is not material. If it survives, offer it as an advanced optional mode—not a mandatory installer path.

Universal-feeling software is built from a maintained matrix, adversarial race testing, and honest telemetry—not a handful of successful manual trials.

Content and race matrix

Use ASCII, emoji and ZWJ families, combining accents, CJK, Arabic/Hebrew RTL, smart punctuation, shell metacharacters, code indentation, tabs, multiline text, and 10,000-character samples under US and non-US layouts.

During transcription, switch app, window, tab, field, selection, modal sheet, and macOS Space. Revoke Accessibility. Change the clipboard between write and restore. Run Clipboard History, third-party clipboard managers, DLP, Universal Clipboard, multiple displays, Stage Manager, and high CPU load.

Release gates

  • Zero wrong-target insertions in 10,000 randomized focus transitions.
  • Zero transcript loss under forced adapter failure.
  • Byte-for-byte restoration of multi-item, multi-type clipboard state.
  • No clipboard overwrite after ownership changes.
  • No insertion into secure fields.
  • At least 99% first-attempt verified success on the published matrix.
  • Crash-free permission denial, AX timeout, stale element, and target termination.
  • p95 delivery below 250 ms after final transcript readiness.

Phased path to a trustworthy v1

Phase 0 · Stop overpromising

Correct product language, add specific failure states and persistent last-transcript recovery, and explicitly reject secure fields.

Phase 1 · Make current delivery safe and observable

Add focus generation, window identity, early tree warm-up, grapheme-safe chunks, adaptive pacing, host-only paste, and distinct delivery outcomes.

Phase 2 · Route and verify

Add verified AX selected-text insertion, paste verification, three product modes, and privacy-preserving local compatibility memory.

Phase 3 · Evaluate native input-source mode

Run the time-boxed InputMethodKit prototype and retain it only when measured gain justifies installation friction.

Phase 4 · Integrate selectively

Consider browser extensions or host plugins only for durable, high-value gaps identified by the compatibility matrix.

The durable advantage is a delivery engine that knows what it can prove, learns coarse compatibility locally, refuses dangerous targets, and never loses the user’s words.
