# Mote historical cleanup benchmark reports

Some preserved run artifacts use the product's former name, Grotdown. They are
historical evidence and have not been rewritten.

This folder contains the reusable reporting system for formal historical cleanup
benchmarks. It turns raw Ollama and MLX cleanup benchmark outputs into a stable
run folder with raw inputs, structured JSON, charts, PDF, DOCX, Markdown, and
rendered PDF QA images.

## Folder Contract

```text
docs/reports/mlx-cleanup-benchmark/
  README.md
  generate_report.py
  requirements.txt
  assets/
  runs/
    YYYY-MM-DD-<short-run-name>/
      metadata.json
      cleanup-results.json
      report.pdf
      report.docx
      report.md
      raw-ollama-cleanup.md
      raw-mlx-cleanup.md
      charts/
        latency-summary.png
        per-sample-latency.png
        model-footprint.png
        pipeline-comparison.png
      qa-render/
        pdf-page-1.png
        pdf-page-2.png
        pdf-page-3.png
        pdf-page-4.png
        pdf-contact-sheet.png
```

`assets/` is reserved for shared report assets. Per-run charts live in each run
folder so old benchmark evidence stays auditable.

## Dependencies

Mote does not depend on these Python packages. They are reporting-only tools.

```bash
python3 -m pip install -r docs/reports/mlx-cleanup-benchmark/requirements.txt
```

## Formal Benchmark Command

Use `formal_cleanup_benchmark.py` for Task 2 formal runs. The command collects
raw Ollama and MLX cleanup benchmark outputs, validates the model/sample shape,
creates a run folder, writes structured JSON, and invokes the Task 1 report
generator.

```bash
/private/tmp/localflow-report-venv/bin/python docs/reports/mlx-cleanup-benchmark/formal_cleanup_benchmark.py \
  --run-label initial-mlx-vs-ollama \
  --run-date 2026-07-06 \
  --ollama-raw /private/tmp/local-flow-ollama-cleanup.md \
  --mlx-raw /private/tmp/local-flow-mlx-qwen25-15b-cleanup-strict-rerun.md
```

Add `--force` only when intentionally replacing a run folder with the same date
and label.

The first implementation is collect-mode: it consumes raw benchmark files that
were generated by the existing Ollama cleanup benchmark and MLX proof tooling.
It does not change app runtime behavior, and it does not make Python part of the
Mote cleanup path.

## Swift MLX Metallib Preparation

Task 4 adds the repeatable native Swift MLX setup step:

```bash
cd Tools/Bench
swift run mlx-metallib-prepare
```

This command queries the installed Xcode Metal Toolchain, compiles MLX Swift's
bundled `.metal` sources, and writes `mlx.metallib` next to the SwiftPM debug
executables. Run it before `swift run mlx-cleanup-spike` on a fresh checkout or
after cleaning `.build`.

Task 4 is a reliability smoke check, not a formal benchmark report. Its audit
folder is:

```text
docs/reports/mlx-cleanup-benchmark/runs/2026-07-06-task-4-metallib-repeatability/
```

## Swift Steady-State Benchmark

Task 5 measures repeated native Swift MLX cleanup calls after one model load and
one warmup generation:

```bash
cd Tools/Bench
swift run mlx-cleanup-steady-benchmark --output ../../docs/reports/mlx-cleanup-benchmark/runs/2026-07-06-task-5-swift-steady-state-cleanup/swift-steady-benchmark.json
```

Generate Markdown, PDF, DOCX, chart, and PDF QA render artifacts from the Swift
JSON:

```bash
/private/tmp/localflow-report-venv/bin/python docs/reports/mlx-cleanup-benchmark/steady_state_report.py \
  --input docs/reports/mlx-cleanup-benchmark/runs/2026-07-06-task-5-swift-steady-state-cleanup/swift-steady-benchmark.json \
  --run-label "Task 5 Swift Steady State"
```

The Task 5 run recorded median repeated cleanup latency of `0.139s`, p90 of
`0.164s`, p95 of `0.166s`, and max of `0.199s` over 24 samples.

## Cleanup Provider Decision

Task 14 promoted MLX to the production cleanup provider after the Task 13
accepted-output filler polish, production-chain acceptance run, and manual
approval of the sample 17 raw fallback. A follow-up cleanup removed the hidden
Ollama fallback path. The current Mote production chain is now:

```text
MLX -> raw transcript
```

The latest decision evidence is:

```text
docs/reports/mlx-cleanup-benchmark/runs/2026-07-08-task-14-mlx-default-provider/report.md
```

Raw transcript fallback remains the terminal safety behavior. Historical
Ollama-vs-MLX reports in this folder remain benchmark evidence, not the current
Mote runtime.

## First Formal Run

The first formal run captures the Phase 3 MLX proof:

- Ollama `gemma3:4b`: median `0.914s`, p90 `1.485s`, first call `12.070s`.
- MLX `mlx-community/Qwen2.5-1.5B-Instruct-4bit`: load `0.489s`, warmup
  `0.180s`, median `0.240s`, p90 `0.264s`.

This historical first-run acceptance decision was `fail` for production
defaulting because the MLX proof still showed formatting and wording artifacts.
Later tasks added sanitizer, plausibility guard, fallback behavior, and the
accepted Task 14 default-provider decision.

## Verification

Run the generator tests with stock Python:

```bash
python3 -m unittest discover -s docs/reports/mlx-cleanup-benchmark -p 'test_*.py'
```

After generating a report, verify:

- `metadata.json` and `cleanup-results.json` parse as JSON.
- `report.pdf` contains the measured values and has rendered QA pages.
- `report.docx` opens structurally with `python-docx`.
- `report.md` contains the measured values and acceptance decision.
- LibreOffice visual DOCX render is attempted when `soffice` is installed.
- `git diff --check` is clean.
